## 15.1 问题与边界

**问题**（R33 / R34，2026-11-10）：用户与助手对项目形成的约定（"发版前先确认"、"推送前跑门禁"）属于记忆的一种，但它的**生效方式**有三种不同诉求：

1. 只想被检索到（普通记忆）；
2. 想让它**每轮生效**（画像 / SOUL）；
3. 想让它成为**仓库级规则**、给所有 agent 读（`AGENTS.md`）。

现状：`AGENTS.md` 是 DSH 原生 workspace 指令入口，插件既不读也不写；R33 只给"可复制片段"，复制粘贴有摩擦。用户裁决：**B 方案**——允许插件在**显式确认**下改写 `AGENTS.md` 的一个托管块；并且当工作区**没有 `AGENTS.md`** 时，插件要有自己的回退体系，不能"没有文件就不支持"。

**边界（写死）**：

- 插件**不接管整份 `AGENTS.md`**：只拥有一个带标记的托管块，块外一字不动；
- **不后台自动写**：每一次写入都必须由用户从提议卡显式发起，看过 diff 并二次确认；
- **不把项目规则当运行时注入层**（有 `AGENTS.md` 时）：避免"第二份规则"与重复注入；
- **只在没有 `AGENTS.md` 时**，插件自管的规则才作为回退注入（§15.5），且一旦文件出现即停止注入（单源原则）。

## 15.2 状态机（按工作区）

| 状态 | 判定 | 生效方式 | 写入资格 |
|---|---|---|---|
| **S0 无 `AGENTS.md`** | 工作区根目录无该文件 | 插件规则域（§15.5）在该工作区对话注入 | 可创建文件（显式确认，走 §15.4） |
| **S1 有文件、无托管块** | 文件存在，无插件标记 | 文件原有内容由 DSH 读取；插件**不注入**自己的规则 | 可添加托管块（显式确认） |
| **S2 有文件、有托管块** | 恰好一个合法托管块 | 文件由 DSH 读取；插件只维护块 | 只能改块（显式确认） |

迁移规则：

- **S0 → S2**：用户在"导出到 `AGENTS.md`"里确认 → 写文件 + 建块 → 规则域记录标 `externalized` 并**停止注入**（单源）。
- **S1 → S2**：显式确认后追加托管块；插入位置默认文件末尾（可配置为 `<!-- rules -->` 锚点，v1 不做）。
- **S2 → S0/S1**（文件或块被删）：**不自动切换注入**。启动/刷新时检测到"已外化但文件缺失/块缺失" → 提示"规则不再生效：重新导出 / 恢复注入 / 删除规则"，由用户选择；避免行为无声变化。
- **手改托管块**：下次同步时以**文件 hash 不符**处理——展示 diff 并要求二次确认，绝不静默覆盖。

## 15.3 托管块格式

```md
<!-- neural-mind:rules:start -->
- 发版前必须先让用户确认 tag / Release / push
- 提交信息使用 feat(scope): / fix(scope): / docs(scope): 前缀
<!-- neural-mind:rules:end -->
```

规则：

1. 标记必须**独占一行**；一个文件**至多一个**托管块（多个 / 不成对 / 不在行首 → 拒绝写入，返回明确原因）。
2. 块内一行一条，`- ` 前缀；规范化规则见 `lib/rules.js`（去项目符号 / 编号、折叠空白、≤200 字符、≤20 条、大小写折叠去重）。
3. **块外内容一字不动**；替换只替换块本身。
4. **行尾风格沿用原文件**（CRLF 文件不写出混合行尾）；原子写（临时文件 + rename），保留文件权限。
5. 空规则集 → 删除托管块（文件其余内容保留），不写空块。
6. 块内文本同时是 UI 展示的"当前项目规则"；`lib/rules.js` 的 `locateRulesBlock` / `parseRulesBlock` / `mergeRulesBlock` 提供解析与合并计划。

## 15.4 写入协议（R34，全部满足才写）

1. **入口**：只从记忆提议卡 / 规则列表的"写入 `AGENTS.md`"按钮发起；先展示**完整 diff**（块前 → 块后）+ 目标路径 + 影响说明。
2. **二次确认**：diff 之后一次显式确认（不是同一次点击）；取消不产生任何写入。
3. **预检**（任一失败即中止并说明原因）：
   - 文件存在 / 可读 / 可写；S0 允许"创建新文件"，但同样需要显式确认；
   - 目标文件内容 hash 与预览时一致（防 TOCTOU）；
   - 托管块结构合法（§15.3），或文件里没有块（追加）；
   - git 工作树干净（`git status --porcelain` 为空；有未提交改动默认拒绝，允许用户显式选择"仍然写入"并二次确认——因为写入会混进用户的未提交改动）；
   - 目标不是符号链接（防写到别处）。
4. **备份**：写入前把原文件字节存入**插件规则域**（`neural_mind_rules` 的备份表，按路径保留最近 5 份 + 审计 hash），**不在仓库里生成 `.bak` / 临时文件**（避免污染工作树）；存插件域可跨重启回滚，卸载/清空插件数据时备份一并消失（文件本身仍在 git 里可恢复）。
5. **写入**：临时文件写完 fsync → rename 覆盖；按文件原编码 / 行尾风格；失败不留下半成品。
6. **审计**：`agents-md-written`（路径、块 hash、diff hash、来源记忆 id、发起会话）；同一路径写 `rules-exported`。
7. **回滚**：提供"撤销上次写入"——仅当文件当前 hash 仍等于写入后的 hash 时可用（否则展示当前 diff，交给用户）；回滚写 `agents-md-reverted`。
8. **状态同步**：成功后规则域记录标 `externalized`（含 `filePath` / `fileHash` / `blockHash` / `lastSyncAt`），停止 S0 注入；`lib/rules.js` 只负责算出 `after`，文件操作与审计在接线层。

## 15.5 无 `AGENTS.md` 时的回退体系（S0）

**目标**：没有仓库规则文件时，项目约定仍然能"每轮生效"，且不依赖用户手工创建文件。

- **存储**：独立短命域 `neural_mind_rules` v1（per-record，按 workspaceId 一行）：
  `{ id: '<workspaceId>', rules: [{ id, text, createdAt, sourceMemoryIds: [] }], updatedAt, externalized: false }`。
  独立域 = 不动主域版本、失败可整体退化（与 §14 `neural_mind_usage` 同一模式）。
- **入口**：规则只能来自**用户权威来源**的记忆（§15.6）或用户在规则列表里手工添加；每条规则带来源记忆 id，可点开回溯。
- **注入**：仅 S0 生效，且**默认关闭**（`projectRulesInject` 默认 `false`，用户在设置里显式打开才注入；关闭时规则只存不注入，列表照常可见）；开启后作为独立短段注入到该工作区对话（放在画像段之后、记忆段之前），标题注明"项目规则（插件管理；写入 `AGENTS.md` 后可共享）"；预算初值 **≤600 字符 / ≤20 条**，超限按优先级截断并在审计 `rules-inject-truncated` 留痕。
- **单源原则**：检测到目标工作区出现 `AGENTS.md`（启动 / 每轮轻量 stat 或定时检查）→ 立刻停止 S0 注入，并提示迁移（§15.2 S2→ 处理）；**绝不同时注入文件和插件规则**。
- **导出**：规则列表提供"导出到 `AGENTS.md`"（显式确认 → §15.4）；导出成功后规则域保留原文与证据，标 `externalized`，供 UI 展示与漂移提示。
- **删除规则**：用户从列表删除 = 归档（不物理删来源记忆）；已 externalized 的规则删除时提示"文件里的托管块仍需手动同步"。

**配置**（2026-11-11 用户裁决：S0 注入**默认关**，需显式开启）：初版只新增 1 项 `projectRulesInject`（bool，默认 `false`）；字符 / 条数预算硬编码（600/20），若后续要可调再加项。**未接线前不进 §10 账本**；接线时账本 70 → 71 并同步设置页。

## 15.6 来源与提权防线

**记忆 → 指令文件是一条提权路径**，因此：

1. **只允许用户权威来源**：用户原话 / 用户确认过的记忆 / 用户手工添加；`source: assistant`（助手推断）、`quote`（外部资料）、`unknown` **禁止**写入托管块或进 S0 注入。
2. **内容检查复用**：写入前跑 `detectSecret` 与注入特征检测（`detectInjection`），命中拒绝并审计（与 SOUL 通道同口径）。
3. **人工闸不可绕过**：diff + 二次确认 + 显式入口；任何后台/自动写入路径都不存在。
4. **可撤销**：回滚与备份（§15.4）；审计可查"哪条记忆、哪次会话、谁点的"。
5. **不读块外内容**：插件只解析自己的托管块，不把 `AGENTS.md` 其他内容当数据（避免外部注入借道；也避免与 DSH 的读取职责重叠）。

## 15.7 与 R33 的关系

- **R33 决定"这条约定该不该是项目规则"**（证据门 / 主体作用域门 / 权威后果门；见 [NEXT_STEPS](../NEXT_STEPS.md) §3.1.2）。
- **§15 提供"项目规则如何落地与生效"**：托管块写入（R34）与无文件回退（S0）。
- 实现顺序：R33a（纯函数标注 + 离线评估，行为不变）可先做；R33b（提议通道 + UI）复用 §15 的写入协议与规则域；两处共用 `lib/rules.js`。

## 15.9 降级矩阵

| 失败点 | 表现 | 降级 |
|---|---|---|
| 规则域打不开 | 无规则列表 / 无 S0 注入 | 退化为"无项目规则"；记忆与对话照常；stderr 一次 + 审计 |
| 目标文件只读 / 被占用 | 写入失败 | 明确报错；保留 diff 供复制；不重试、不后台写 |
| 托管块结构异常 | 拒绝写入 | 展示原因 + 建议手工修复；不自动"修复" |
| 工作树不干净 | 默认拒绝写入 | 允许用户显式二次确认后继续（记录审计） |
| 文件 hash 变了（TOCTOU） | 拒绝写入 | 重新加载并展示新 diff |
| S0 注入超预算 | 截断 | 审计 `rules-inject-truncated`；页面提示条数 / 字符上限 |
| S2 块被手改 | 同步时 hash 不符 | 展示 diff，需二次确认才覆盖；否则保持文件现状 |

## 15.11 明确不做

- 不接管 / 重写整份 `AGENTS.md`；不读、不解析块外内容；
- 不后台自动写、不在没有显式确认的情况下创建/修改文件；
- 不在有 `AGENTS.md` 时注入插件规则（不做第二份规则）；
- 不在仓库里生成 `.bak` / 临时备份文件；
- 不做嵌套子目录 `AGENTS.md`（v1 只认工作区根；DSH 原生读取行为不受影响）；
- 不把 `quote` / 助手推断当规则来源；
- 不新增依赖。

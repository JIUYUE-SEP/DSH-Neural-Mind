# §5 检索:混合双路(决策②)

> 覆盖节号：§5.1、§5.2、§5.3、§5.4、§5.5、§5.6


**关键词路 + 向量路 + RRF 融合,刻意不做 LLM 重排。**

- **关键词路(始终开启)**:内存 BM25,全文索引不分段;单路及格线 `bm25.minScore` 0.1;**BM25 绝对分随语料规模漂移**(v1.8):池子变大后若及格线形同虚设/误杀,启用相对及格线 `bm25.minScoreTopRatio`(默认 0=关闭;>0 时取 top1 得分 × 该系数,与绝对线取较严者)——**top1 取自未过 eligible 的 BM25 命中**(archived/hidden 的高分也会抬高相对线,属已知弱面)
  - **分词**:CJK 字符级 2/3-gram + **拉丁文按词切分 + camelCase/snake_case 二级切分**(`hotBufferMaxEntries` → hot/buffer/max/entries;`auth_token` → auth/token;索引与查询同构;注意切分后统一小写)
- **向量路(配置后开启)**:**自适应分段**——≤`chunkPlainMaxChars`(默认 8K 字符,8192)整条单向量;>此值按 `chunkSize`(默认 1000 字符)+ `chunkOverlap`(默认 100 字符)切段,每段一个向量,写入时批量一次调用(**仍是一次请求,但因段间重叠,总字符/token 略高于全文(约 +段数×overlap)**,不是"完全等价")。命中段**归并到父记忆去重**,向量路名次取各段最高者(max-pooling)。单路及格线 `vectorMinScore` cos ≥ 0.2;查询 embed 内联预算 ≤150ms(`semanticSearch.timeoutMs`)超时降级纯 BM25;`embeddingModel` 指纹不符忽略向量路。**换模型重嵌入节流(v1.8)**:后台分批(每批 ≤ `reembedBatchSize` 默认 64 条)、单并发、批间让路 1 秒、**启动即可跑**(v1.9 复核:文档原写"仅空闲时跑",实现里没有空闲门控——它只在向量路可用时启动,靠单并发与批间隔不抢内联预算),完成前向量路对指纹不符的条目降级纯 BM25——重嵌入不打爆速率限制)。**向量维度防呆(v1.13)**:嵌入响应当场校验维度——同一次响应内不等长按 `shape` 降级;**跨响应维度变化**(端点换了模型但 `modelId` 没改)记 `dim-mismatch` 并降级纯 BM25,绝不把两种维度的向量混用(cosine 对不等长会静默返回 0);检索侧发现库中向量维度与当前查询向量不符时跳过该段并计入降级账(日志/触发节流 5 分钟),同时触发后台重嵌入自愈——`modelId` 未改但端点换模型不再无声失效
- **embedding 无 DSH 官方接缝**:插件自建 HTTP 通道,凭据走 `packages/credentials`;模型名必须可配
- **本地无鉴权端点(v1.9 补)**:`semanticSearch.apiKeyOptional`(默认 false)。开启后空凭据不再关闭向量路,请求也不带 `Authorization` —— 自建 ONNX 服务/Ollama 这类本机端点无需编造假密钥。**降级可观测(v1.9 补)**:失败按原因聚合写审计 `embed-degraded`(`timeout` / `network` / `http-<status>` / `shape` / `no-key` / **`dim-mismatch`**——检索侧跳过旧维度向量时同样累加该原因),首次立即落一条、其后每 10 次或每 5 分钟一条——兑现"降级率供校准",同时不逐次刷屏;`no-key` 专门覆盖"配了端点却没配凭据"这个静默失效路径
- **本地服务生命周期托管(v1.9 补)**:`semanticSearch.autoStartCommand`(默认空 = 不管)+ `autoStartWaitMs`(就绪审计窗口,默认 20s)。本地 embedding 服务随 dsh 进程生灭:启动时探测 `baseUrl` 端口,没人监听才拉起;进程退出即回收。三条纪律——① 端口已被监听一律当**外部服务**,不重复拉起也不杀(别人起的别人管);② 回收靠**子进程 stdin 管道 EOF**,不轮询 PID(父进程正常退出 / Ctrl-C / `kill -9` 都成立,且避开 PID 复用误判);③ 失败只记账(`embed-sidecar-started`/`-external`/`-ready`/`-unready`/**`-late-ready`**(超过审计窗口后才就绪)/`-failed`),向量路照旧降级纯 BM25。**不是通用进程管理器**:只管一条用户显式配置的本地命令,且仅当向量路启用时生效。**平台限制**:看门狗固定走 `/bin/sh -c`(`lib/sidecar.js:156`)——**仅 POSIX**;Windows 下 `autoStartCommand` 起不来,只记 `embed-sidecar-failed`、向量路照旧降级纯 BM25
- **就绪即预热(v1.9 补)**:`semanticSearch.autoStartWarmup`(默认 false)。本地服务懒加载——端口在听不代表模型在显存,不预热则**第一条检索**必然撞查询预算(`semanticSearch.timeoutMs`,默认 150ms)而白白降级一次。开启后边车就绪时用**真实 embedder** 发一次极小调用(预算独立且宽松,冷加载几十秒也够,不占查询份额),记 `embed-sidecar-warmed`(含耗时)/ `-warmup-failed`;**预热必须取运行时"当前这一代"的 embedder**(边车是进程级、跨热重建存活,而启动时先按 cordis 基座配置 boot 一次、设置层附着后才热重建出真正带端点的 embedder;抓住旧闭包会 `available()=false` 哑火 0ms);**外部服务不预热**(不是我们起的,不替它占显存)。代价:dsh 运行期常驻显存,故默认关
- **融合**:两路各自 top(2×injectMaxItems),RRF(`rrfK`=60);**不设全局 minScore**(单/双路分值域差一倍),只保留单路及格线 + topK 截断
- **绝对相关性闸门(§5 v1.9,`relevanceGate`;v1.13 起默认开)**:RRF 是**名次制**,噪声查询的 rank-1 与真实相关的 rank-1 同样得 `1/(k+1)`,所以"相关度"对排序几乎没有鉴别力(实测:噪声查询的条目 rel 0.0307 ≈ 双路命中满格 0.0328)。补法是在**注入**前用**每路的原始分**(BM25 原始分 / 向量 cos)做准入:**两路都过共识线**(默认 cos 0.35 / bm25 2)→ 放行;**只有一路命中 → 该路须过更高的单路线**(默认 cos 0.55 / bm25 10)。三条纪律写死:① **只作用于注入路径**,recall 是用户主动问、保持宽松;② **纯 BM25(未配 embedding / 服务降级)时用单路绝对门槛 `bm25OnlyMin`(v1.13 引入默认 2;0.6.6 R18 校准到 10)准入**——旧行为是"整条闸门不生效",于是没有向量路的用户每轮都被弱词面命中铺满注入预算(2026-11-07 用户反馈:注入过多 + 错误注入);池子大小按 `corpus.size`(全量记录数,**含 archived/hidden**,不是可检索池)判定,小于 `bm25OnlyMinPoolSize`(默认 30)时不启用,防小池子绝对分漂移误杀(§5.6);③ **不做路级交集**(那会把"只有一路命中"的正当情况一律砍掉:改写查询靠向量、标识符查询靠 BM25)。**实现口径(2026-09-17 对齐注释与实现)**:BM25 侧取的是**未施加单路及格线之前**的原始分(`minScore`/相对线都还没过滤),所以"过共识线"不蕴含"已过单路及格线"——被 top-N 截掉、或被抬高的相对线压掉的条目若在向量路命中,仍可能靠原始分过共识/单路线放行(默认绝对线 0.1 低于共识线 2,"被绝对线切掉还过共识"在默认配置下不可达);两路各自仍须过 `eligible()` 硬过滤(这两点已写进 `lib/search.js` 闸门段的注释)。**实测(2026-09-17 重跑,真池子 566 条)**:当时 22 条带 id 正例(**现夹具为 POS 18 + CROSS 2 = 20 条**,以 `tools/eval-fixtures.mjs` 为准)+ 4 条负例 → 基线 R@5 **0.73**、负例均注入 **5.0**;闸门档 R@5 **0.73(持平)**、负例均注入 **1.0** —— 收益是**降噪,不是提升召回**;对照(同次重刻口径):纯 AND R@5 0.45~0.59 / 负例 0.0,纯 OR 前沿(cos≥0.55 & bm25≥2)R@5 0.77 / 负例 4.8。**v1.13 默认值**:`enabled=true` + 新增 `bm25OnlyMin=2` / `bm25OnlyMinPoolSize=30`;**0.6.6 R18 校准(2026-11-09,frozen-v2 双路径)**:纯 BM25 档 `bm25OnlyMin` 2→**10**,负例注入 **6/13(均 2.15 条)→ 2/13(均 0.77 条)**、R@1 **0.973 → 1.000**、R@5 不变;混合路不受影响(2/13、R@1 1.0)。评估工具 `--lane bm25|hybrid|both` 两条路径分开报(`tools/eval-frozen.mjs`),`bench-results/frozen-v2.json` 同时存两组指标;冻结集(frozen-v1,16 条池子)复测:负例注入 5/5 → **1/5**,正例平均注入 **4.6 → 1.4** 条,R@1 0.75 → 0.875、R@5 1.00 → 0.875(该集用确定性假向量,口径见 `docs/legacy/review-provenance.md` v1.13;真池子 2026-09-17 实测 R@5 持平)。**数字随池子快照漂**(正例目标本身就在池子里),引用必须带日期、池子规模与命令。工具 `tools/gate-sweep.mjs`(扫描)是独立复刻(未走 `eligible`/冷启动,截断顺序与线上相反),`tools/inject-eval.mjs`(真路径复验)走真实链路——两者用途不同、**非逐条等价**,数字须一起看、不能互相替代
- **天花板**:全局数万条记忆(含段)内存规模;超出再引入专用索引(远期,可从 chunks 零迁移重建)

### 排序公式

```
最终分 = 相关度(BM25/向量,经 RRF) × 时间衰减 × 证据系数 × 籍贯系数 × entity 加权
         × supersededFactor(被取代 ×0.3) × validUntilFactor(事件过期 ×0.3)
         × validUntilFactor(state TTL 到期宽限期内再 ×0.3,可与事件过期叠加,最低 ×0.09)
         × stagedFactor(暂存 ×0.7)
```

(importance 刻意不在公式里——防 LLM 自评刷分主导排序;只管衰减豁免/配额/开场平局决胜。)

### 5.1 相关度

**BM25**:`k1=1.5, b=0.75`;`IDF(t)=ln(1+(N-n(t)+0.5)/(n(t)+0.5))`;分词见上。

**向量**:段级余弦 `cos(q,d)=(q·d)/(|q||d|)`;一条记忆的向量路得分 = 各段最大值。

**RRF(k=60)**:`相关度(d) = Σ 每一路: 1/(60+该路名次)`,未进榜不贡献。按名次融合,绕开归一化失真;两路都沾边的条目赢过单一路冠军。

### 5.2 时间衰减:阶梯打折,以"最后触动"为基准

```
距今(最近一次 reinforce 事件或创建,取新者)   <7天    <30天    <90天    ≥90天
系数                                       1.0     0.8      0.5      0.3(保底)
```

- **基准是最近 reinforce(印证)时间**,不是创建时间——常被印证的老记忆永远新鲜;challenge 不刷新新鲜度
- **豁免**:`temporal='pattern'`(**配额降级 `noExemption=true` 者除外,改走阶梯**)或 `importance≥8` → 恒 1.0(配 §3.4 配额防刷分,带最小名额)
- 阶梯而非连续函数:可预测、可调试

### 5.3 证据系数:事件明细账 → 衰减求和 → S 曲线映射

```
第一步,对 evidence[] 明细逐条衰减求和(读时惰性计算):
  R = Σ reinforce 事件: weight × 0.5^(距今/30天)
  C = Σ challenge 事件: weight × 0.5^(距今/180天)   ← 一次打脸,记很久
  weight:用户显式 = 1.0;系统推断 = 0.5(evidenceWeights,§10;
        用户显式的落点(v1.24 R13b 收窄)= 设置页暂存确认 + remember 的 userQuote 核对通过;
        模型自填 confirm 不再算用户显式(记系统推断);提炼侧关系判定一律系统推断;
        **重复出现(v1.22 R14)= 系统推断 0.5**:提炼去重命中 active 条目、
        memory_remember 命中 active 条目各记一条 reinforce,同批同内容只记一次;
        用户质疑(weight ≥ 1.0 的 challenge)的条目,重复出现不能清 negativeSince)

第二步,净分:E = R − C

第三步,logistic 映射:证据系数 = 2/(1+e^(−E·slope)),slope = `evidenceLogisticSlope`(默认 1.0,§10)
  E=0 → 恰 1.0(中立);E=+2 → ≈1.76;封顶趋近 2 倍;E=−2 → ≈0.24(均按 slope=1.0 计)
  已知特性(v1.8):单次用户显式印证(weight 1.0)即把系数推至 ≈1.46(2/(1+e^−1),2026-09-17 复核:
  原文写的 ≈1.54 是算错的数,`lib/rank.js` 与 `test/rank.test.mjs:135` 都按 1.46 断言),单事件增益偏大——
  刻意保留以示"用户亲口分量重";若 V2 实测出现刷分/震荡,先调 slope(如 0.67 ≈ E/1.5 拉伸)再动权重
```

### 5.4 籍贯、entity 与暂存降权(查表 + 硬过滤)

```
当前 workspace      × workspaceBoost(默认 1.0)
其他 workspace      × remoteFactor(默认 0.8;收紧期 0.5,及格线 ×2)
                    ——只分两档,不做同仓亲和(monorepo 兄弟包不区分,2026-09-17 裁决,§9 第 24 条)
entity 重合         × entityBoost(默认 1.1)——entity 与当前 cwd 子路径重合,
                      或本会话近 entityWindowTurns(默认 3)轮消息直接提及该 entity 时
被取代条目          × supersededFactor(默认 0.3)
过期事件条目        × validUntilFactor(默认 0.3;todo 行动项不适用,§6)
过期 state 条目     × validUntilFactor(默认 0.3;`expiresAt` 已过且宽限期内;`importance≥8 且 E≥0` 免)
                    ——与"过期事件"是两个独立分支,可叠加(最低 ×0.09)
staged 条目         × stagedFactor(默认 0.7,staged 专属降权;staged 证据恒从 0 起步)

硬过滤:privateWorkspaces 名单内 → 外地不可见;sensitive 条目 → 打开 sensitiveNoCross
时(默认关,0.6.6 R4 起)不跨 workspace(含 L0 初筛标记与常驻补位);hidden → 检索/召回/注入域不可见
(**管理视图 `owner` 例外,见 §4**);archived 仅 recall/owner 可见;
检索固定 global
```

### 5.5 算例

当前在项目 A 问"这个项目依赖管理用什么来着":

| | 记忆 X:"项目统一用 pnpm"(A 项目,pattern,3 天前被用户显式确认 1 次) | 记忆 Y:"上次用 npm 装包报了个警告"(B 项目,episode,20 天前,无证据) |
|---|---|---|
| 相关度 | BM25 第1 + 向量第2 → 1/61+1/62 ≈ 0.0325 | 仅 BM25 第4 → 1/64 ≈ 0.0156 |
| 时间 | pattern → 1.0 | 20 天 → 0.8 |
| 证据 | E≈0.93 → 2/(1+e^−0.93) ≈ 1.43 | E=0 → 1.0 |
| 籍贯 | 1.0 | 0.8 |
| **最终分** | **≈ 0.0465** | **≈ 0.0100** |

X 以约 4.6 倍胜出(两任红队各自复算,均吻合)。

### 5.6 参数校准说明

所有参数(k1/b、及格线、加权系数、半衰期、阶梯档位、分段尺寸、阈值、配额、预算)均为起点值,**可调配置全部经 §10 暴露**;代码里另有少量**未暴露的机制常量**——写入路 embedding 30s、预热 60s、连接测试 10s、降级账 10 次/300s、维度告警节流 300s、state 宽限 7 天与归档宽限 2×TTL、边车探活 700ms——以及**展示上限**(recall 单条渲染 1200 字符、展开原文片段 2000 字符,`lib/tools.js:16,230`);这些都不是部署旋钮,调它们要改代码并重发。V2 用真实使用数据校准。**降级率的去向**:embedding 降级写持久审计 `embed-degraded`(按原因聚合);核验失败改证据分并挂渲染标记(不写审计);压力跳过只进注入日志(进程内环形缓冲,**不落盘**)——想要落盘降级率,需另加计数。

**分值域说明与算例回归纪律(v1.8)**:RRF 按名次计分,相邻名次差距 <2%(rank1 ≈ 0.0164,rank10 ≈ 0.0143),相关度本身区分度有限——**最终排序由系数主导是刻意的**(本地优先、证据优先、新鲜优先),不是缺陷。配套纪律:§5.5 算例集即排序回归测试;新增或调整任何系数/及格线时必须扩充算例并锁定期望排序(至少覆盖"本地弱相关 vs 异地高相关""高证据老记忆 vs 无证据新记忆"两组边界),防参数漂移造成倒挂;校准时优先调及格线与系数,不动 RRF 常数。

**绝对线随池子漂移(2026-09-17 复核)**:`consensusBm25` / `soloBm25` 是**绝对 BM25 分**,其等效严格度随池子规模、文档平均长度与分词分布漂移(**cos 是归一化量,同一模型内可比;换模型阈值须重扫**,`embeddingModel` 指纹会让旧向量作废);`bm25.minScoreTopRatio` 已是相对线的先例。因此 0.35/2/0.55/10 只是**起点值**——长期运行或换池子后应重扫:`tools/gate-sweep.mjs` 负责扫描矩阵,`tools/inject-eval.mjs` 负责在真实注入路径上复验(gate-sweep 是独立复刻、未走 `eligible`/冷启动,二者**非逐条等价**),两者数字必须一起看。**v1.13 同理**:纯 BM25 的 `bm25OnlyMin` 也是绝对分,故加 `bm25OnlyMinPoolSize`(默认 30)护栏——小池子不启用,避免"新用户头几十条记忆一条都注入不进来"的误杀;池子长大后按真实池子重扫。**0.6.6 R18 更新**:`bm25OnlyMin` 2→10 是 frozen-v2 上"纯 BM25 默认档"的校准值(负例 6/13→2/13、R@1 0.973→1.000);它同样是绝对分,换池子或换语料分布后仍要走 `gate-sweep` / `inject-eval` 重扫。
